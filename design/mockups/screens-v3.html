Caseflow · Screens v3: pipeline drag and drop

ADR-0014 and PLAN T18b. Each frame is the real /pipeline markup, rendered from the components with the seeded-style rows, and styled by the app's own compiled Tailwind CSS. Only the drag states are new. The toolbar, header, sidebar, cards and Move menu are unchanged.

What you're approving (T18c and T18d use exactly these)

  1. Drop target, on the column section: data-drop-target:bg-accent-soft data-drop-target:outline-2 data-drop-target:-outline-offset-2 data-drop-target:outline-dashed data-drop-target:outline-accent. The dashed outline is the non-colour cue, and it stays visible in forced colours. The card's own column never gets it.
  2. Source card, on the li left behind. Recommended Adata-dragging:border-dashed data-dragging:border-lead-border data-dragging:bg-track: an outlined slot, with text at full contrast (Lead ink-2 on track is 5.2:1). Option Bdata-dragging:opacity-50: the plain fade, but the grey text drops to about 2.3:1, which axe flags while a keyboard drag is in progress (frame 3).
  3. The dragged copy: <ul inert class="m-0 list-none rounded-lg p-0 shadow-lifted [&>li]:border-lead-border"> around the same card, as wide as the source. The border is the card's own hover border, so the copy's edge holds in dark mode over a card of the same colour. shadow-lifted is a new token in globals.css: --lifted: 0 12px 28px -8px rgb(30 42 38 / 0.24), 0 2px 6px rgb(30 42 38 / 0.08), dark 0 12px 28px -8px rgb(0 0 0 / 0.7), 0 2px 6px rgb(0 0 0 / 0.45). The alternative is the existing shadow-overlay, which casts to the left because it was made for the filter panel.
  4. The Drag button, after Move to… in the card: the house ghost Button, grip icon plus "Drag", named "Drag {name}", 28px high. It sits at the right end of the Move to… row: absolute right-3 bottom-2.5 z-1 h-7 px-2 text-xs opacity-0 not-focus-visible:pointer-events-none focus-visible:opacity-100 max-md:hidden. It takes no space while hidden, so nothing shifts when it appears, and it doesn't block a click on the card.

Not shown, because a still frame can't: dnd-kit's grabbing cursor while dragging, the 150ms ease-out drop (none under reduced motion), and the toast after a drop, which is the menu's own "{name} moved to Active."
