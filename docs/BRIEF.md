# Brief: Senior Frontend Engineer case study (verbatim)

Received 2026-11-16. Submission due within 24 hours of receipt.

## 1. What to Build
Build and deploy a small CRM web application for a law firm's client intake team. The application should be simple and lightweight. We value quality, usability, and attention to detail more than the number of features implemented.

## 2. Core Features
- **Contacts List:** A contacts list with search functionality, filtering by status (Lead, Active, Closed), and sorting.
- **Contact Details Page:** A detailed view displaying the contact's information, notes, and an activity timeline.
- **Create & Edit Contact Forms:** Forms to create and edit contacts, including validation and clear error messages.
- **Pipeline View:** A simple board with one column per status. Users should be able to move contacts from one status to another.
- **Application States:** Loading, empty, and error states must be implemented on every screen.

## 3. Technical Requirements & Guidelines
- You may use any modern framework; however, React or Next.js is preferred.
- You may use a mock API, local storage, or a free backend service such as Supabase.
- Data must persist even after refreshing the page.
- The application must be responsive, work well on desktop, and remain usable on mobile devices.
- You are allowed to use AI tools. However, you must understand every line of code and be able to explain your implementation during the technical discussion.
- Generic AI-generated UI and copy will count against your assessment.

## 4. Submission Requirements
- **Live Application:** A deployed Vercel link to a fully functional application that we can access, test, and use. Mandatory; submissions without a working live Vercel link will not be reviewed.
- **GitHub Repository:** Clean and meaningful commit history. Do not squash all work into a single commit.
- **README (max one page):** component structure and state management approach; reasoning behind main UI/UX decisions; one tradeoff and what you would improve with more time; how you used AI tools.

## 5. Assessment Criteria
- UX & Visual Judgement: visual hierarchy, spacing, clarity, and application states.
- Code Quality: code structure, naming conventions, reusability, and use of types.
- Product Sense: approach to prioritizing features and deciding what to build first.
- Communication & Decision-Making: explaining technical decisions in the README and during a 30-minute walkthrough call.

## 6. Deadline & Expected Time Commitment
Within 24 hours of receiving the case study. Expected completion time approximately 6–8 hours.
